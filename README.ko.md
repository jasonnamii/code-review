# code-review (코드리뷰)

> 🇬🇧 [English README](./README.md)

**백엔드·프론트·Android·iOS·AI/ML — 파트가 달라도 하나의 정밀 리뷰 엔진. 코드 변경을 개발자가 바로 고칠 수 있는 리포트로, 거짓양성은 걸러서.**

## 문제

작성자는 의도한 정상 경로는 잘 짠다. 버그는 바뀐 줄이 아니라 **그 변경이 깨뜨린 주변 가정**에 산다. 일반 린터·LLM 리뷰는 거짓양성으로 신호를 묻고, 파트마다 언어·역할이 달라 도구가 갈린다.

## 해법 — 보편 8축 척추 + 파트별 렌즈

- **역방향 TDD**: 테스트를 먼저 쓰듯 **통과 기준을 먼저** 세우고, 그 기준으로 코드를 역검증. diff는 검증 대상이 아니라 원료.
- **보편 8축**(정확성·상태/동시성·에러·계약·보안·성능·구조·테스트)은 모든 파트 공통. **파트 렌즈**(백엔드·프론트·Android·iOS·AI)는 "어느 축이 치명적이고 어떻게 터지나"만 바꾼다.
- **적대적 검증**: 모든 결함은 반증 시도를 통과해야 보고. 거짓양성 1건이 리뷰 신뢰를 깎는다.
- **지식 기반 추론**: 패턴 매칭이 아니라 코드 의미 모델 위에서. 카탈로그는 근거지 트리거가 아니다.

## 흐름

```
입력: diff/PR 또는 대상 파일
   ↓ Phase 0    정규화 + 파트 식별 + 렌즈 로드 + 레드플래그 선행 스캔
   ↓ Phase 0.5  코드 의미 모델(의도·계약·자원·상태·불변식)
   ↓ Phase 1    통과 기준 역생성(8축 + 파트 렌즈 + 디텍터)
   ↓ Phase 1.5  시스템 파급(호출자·호출처·마이그레이션·횡단)
   ↓ Phase 2    역검증 → 발견 + 적대적 검증(거짓양성 제거) + 신뢰도
   ↓ Phase 3    처방 → 패치 + 근거 (보안·라이선스는 라우팅)
   ↓ Phase 3.5  승격(미학 모드) → 구조 상위설계 제언
출력: 스캔 가능한 리뷰 리포트(.md) + 옵션 PR 인라인 코멘트
```

## 파트 (하나의 엔진, 여러 렌즈)

| 파트 | 렌즈 강조 |
|---|---|
| 백엔드 | 동시성·트랜잭션·API계약·N+1·인증인가·멱등성 |
| 프론트 | 렌더/상태·effect 누수·접근성·번들·XSS |
| Android | 생명주기·Context누수·메인스레드(ANR)·코루틴스코프 |
| iOS | retain cycle·메인스레드UI·강제언래핑·async |
| AI/ML | 데이터누수·재현성·지표오용·프롬프트인젝션·비용 |

멀티파트 PR은 렌즈를 모두 얹고 **파트 경계 계약**(예: 백엔드 API 변경이 앱을 깨나)을 추가로 본다.

## 행동 × 타깃 × 웨이트

- **행동**: 진단 / 처방(기본) / 승격(미학)
- **타깃**: diff리뷰(기본) / 전체감사
- **웨이트**: 라이트(치명만) / 표준(8축 전수, 기본) / 헤비(보안·동시성·성능·테스트·승격)
