# 보안·비밀값·라이선스·PII 디텍터 — 감지 + 라우팅

8축 중 보안축의 정밀 분기. **코드 결함(인젝션·권한·검증)은 처방까지**, **법무·라이선스·규제 적합성 판단은 감지·라우팅만**(생성 ✗ — 절대규칙 6). 디텍터는 의미 모델에 비춰 ●○-로 판정하고, 적대적 검증으로 거짓양성을 거른다.

> 경계선: "이 코드가 공격당하나"(처방 OK) vs "이게 라이선스·규제·법적으로 적법한가"(라우팅). 후자를 직접 단정하면 무자격.

---

## D1 — 인젝션 (처방 OK)

| 종류 | 신호 | 처방 |
|---|---|---|
| SQL/NoSQL | 입력으로 쿼리 문자열 조립, ORM raw, 동적 `WHERE` | 파라미터 바인딩, ORM 안전 API, 입력 타입 강제 |
| 명령 | `exec`/`system`/`shell`에 입력 결합 | 인자 배열·allowlist, 셸 미경유 |
| 템플릿/코드 | `eval`·동적 템플릿에 입력 | 제거·샌드박스·정적 템플릿 |
| 경로 traversal | 입력으로 파일 경로 구성(`../`) | 정규화 + 베이스 디렉터리 제한 |
| LDAP/XML/헤더 | 입력이 필터·XML·헤더로 | 이스케이프·검증 |

## D2 — 인증·인가 (처방 OK)

- **authz 위치**: 매 요청·서버에서 검증되나? 클라이언트만 믿나? 메서드 단위 누락?
- **IDOR**: `/orders/{id}`에서 id 소유자 확인? 다른 사용자 객체 접근 가능?
- **수직/수평 상승**: 일반→관리자, 사용자 A→B 자원
- **인증 우회**: 토큰 검증 누락·만료 미확인·서명 미검증(JWT `alg:none`), 세션 고정
- **응답 일관성**: 로그인·가입·재설정이 계정 존재를 드러내나(계정 열거)

## D3 — 입력 검증·출력 인코딩 (처방 OK)

- **XSS**: `dangerouslySetInnerHTML`·`v-html`·미이스케이프 출력 → 출력 인코딩, 신뢰 입력만
- **SSRF**: 입력 URL로 서버가 요청 → allowlist·내부 IP 차단
- **오픈 리다이렉트**: 입력으로 리다이렉트 → allowlist
- **역직렬화**: 신뢰 안 된 데이터 역직렬화(pickle·Java 직렬화) → 안전 포맷·스키마 검증
- **정규식 DoS**: 백트래킹 폭발 정규식에 입력 → 안전 패턴·타임아웃
- **대량 할당(mass assignment)**: 입력을 모델에 통째 바인딩 → allowlist 필드

## D4 — 암호·비밀값 (처방 OK + 일부 라우팅)

- **약한 암호**: MD5/SHA1로 비번, ECB, 짧은 키 → bcrypt/argon2/scrypt, 인증 암호화
- **약한 난수**: 보안용 `Math.random`/`rand()` → CSPRNG
- **평문 저장·전송**: 비번·토큰·PII 평문, HTTP → 암호화·TLS
- **하드코딩 비밀**: 키·토큰·비번이 코드·설정·커밋에 → 시크릿 매니저, **이미 커밋됐으면 키 로테이션 + 라우팅**(노출 사고는 보안팀)
- **노출**: 로그·에러·URL 쿼리·클라이언트 번들에 비밀/PII

## D5 — PII·개인정보 (감지 + 라우팅, 생성 ✗)

- PII(이름·연락처·주민·위치·결제)가 **로그·프롬프트·외부 전송·학습데이터**에 평문으로?
- 수집 최소화·보관·파기 정책이 코드에 반영됐나? → **감지만**, 적법성 판단은 라우팅
- → `regulatory-skill`(규제), `app-and-jang`(개인정보처리방침·고지). "전문 검토 필요" 1줄.

## D6 — 라이선스·OSS (감지 + 라우팅, 생성 ✗)

- 새 의존성·복붙 코드의 라이선스가 프로젝트와 충돌(카피레프트 GPL/AGPL을 독점 제품에 등)?
- 라이선스 고지·귀속 누락? → **감지만**, 적법성·귀속 판단은 `ip-skill` 라우팅. "라이선스 검토 필요" 1줄.

## D7 — LLM/AI 보안 (처방 OK + 일부 라우팅)

- **프롬프트 인젝션**: 사용자 입력이 시스템 프롬프트·도구 호출 오염 → 입력 분리·구분자·권한 최소화
- **출력 신뢰**: LLM 출력을 검증 없이 실행(코드·SQL·명령) → 검증·샌드박스·휴먼인루프
- **PII/비밀 in 프롬프트**: 민감정보가 프롬프트·로그로 → D5 연동
- **과도 권한 도구**: 에이전트 도구가 광범위 권한 → 최소권한·승인 게이트

---

## 출력 규칙

| 유형 | 처리 |
|---|---|
| 코드 결함(D1~D4·D7) | 처방 + 패치 + [신뢰도] |
| PII·라이선스·규제 적법성(D5·D6) | **감지·라우팅만** + "전문 검토 필요" 1줄. 직접 적법성 단정 ✗ |

거짓양성 주의: 상수·테스트 픽스처의 가짜 비밀, 내부 전용 경로의 신뢰 입력, 단일 신뢰 환경 — 적대적 검증으로 거른 뒤 올린다.
