# 승격(미학) 모드 — 구조 상위설계 (러비 흡수)

행동=승격일 때만. **진단·처방과 별도 섹션**(🎨 취향·구조). 결함이 아니라 "더 나은 구조"를 제언한다. 취향임을 명시하고 강요 ✗(절대규칙 7). 러셀 구조분해 + 비트겐슈타인 의미검증의 코드판.

> 결함과 승격의 경계: **틀린 것**=결함(🔧). **맞지만 더 좋아질 수 있는 것**=승격(🎨). 승격을 결함으로 올리면 월권·노이즈.

---

## 1단계 — 분해 (지금 구조를 드러낸다)

- 이 코드의 **책임**은 몇 개인가? 한 함수/클래스가 여러 일을 하나?
- **의존 방향**은? 무엇이 무엇을 아나(결합)? 순환 의존?
- **의도가 이름·구조에서 보이나**? 읽는 사람이 추론으로 메워야 하나?
- 같은 개념이 여러 표현으로 흩어졌나(중복·산란)?

## 2단계 — 평가 (어디가 아름답지 않나)

| 기준 | 묻는 것 |
|---|---|
| **응집** | 한 단위가 한 가지 이유로만 바뀌나(SRP) |
| **결합** | 의존이 최소·단방향·추상에 기대나 |
| **의도 표현** | 이름·타입·구조가 "무엇을·왜"를 말하나 (비트겐슈타인: 의미가 쓰임에 드러나나) |
| **대칭·일관** | 비슷한 것은 비슷하게, 다른 것은 다르게 |
| **불필요 제거** | 죽은 코드·과한 추상·조기 일반화·우발적 복잡도 |

## 3단계 — 승격 (상위설계 제언)

- **추출·분리**: 책임 분할, 순수 함수 분리(IO와 로직), 의도 드러내는 이름
- **의존 정리**: 의존 역전, 경계 인터페이스, 데이터/동작 응집
- **표현 통일**: 흩어진 개념을 한 타입/모듈로, 매직 넘버→명명 상수
- **단순화**: 과한 추상 제거, 분기 평탄화, 조기 반환, 불변으로

각 제언: **현재 → 제안 + 한 줄 근거 + (선택) 패치**. "꼭 해야 함"이 아니라 "이렇게 하면 읽기·고치기 쉬워짐". 규모·일정 고려해 과한 리팩터링 강요 ✗.

---

## 출력 예 (🎨 섹션)
```
## 🎨 취향·구조 (선택 — 안 고쳐도 됨)
- order.ts:30-80 — 한 함수가 검증·계산·저장·알림 4가지. 순수 계산(calcTotal)만 분리하면
  테스트·재사용 쉬워짐. (근거: 책임 분리)
- 매직 넘버 `86400`이 3곳 → `SECONDS_PER_DAY` 상수로 의도 드러내기
- cache 키 만드는 로직 중복 3곳 → `cacheKey(id)` 한 곳으로
```

> 승격은 결함 처방을 마친 **뒤** 제시한다. 결함이 많으면 승격은 짧게 — 먼저 고칠 게 우선.
