# 파트별 렌즈 — 하나의 8축을 파트마다 다르게 비춘다

8축(정확성·상태/동시성·에러·계약·보안·성능·구조·테스트)은 **모든 파트 공통**이다. 파트마다 다른 건 ① 어느 축이 치명적인가(강조축) ② 그 축이 이 환경에서 어떤 모습으로 터지나(고유 발현형) ③ 무엇을 먼저 보나(역할 우선순위)다. 렌즈는 8축을 **대체하지 않고 강조·번역**한다.

> 사용법: Phase 0에서 파트 판정 → 해당 렌즈 로드 → Phase 1에서 8축에 렌즈의 강조축·발현형·레드플래그를 얹는다. 멀티파트 PR은 렌즈를 모두 얹고 **파트 경계 계약**을 추가로 본다.

> ⛔ 렌즈도 매칭이 아니다(`reasoning-method.md`). 항목은 의미 모델에 비춰 ●○-로 판정하고, 결함은 적대적 검증을 통과해야 확정한다. 처음 보는 언어·프레임워크는 구조 유추로 보되 고유 함정은 [신뢰도: 하]로.

## 파트 판정 신호 (Phase 0)

| 파트 | 확장자·경로·신호 |
|---|---|
| **백엔드** | `controller`·`service`·`repository`·`handler`·`api/`·`.go`·`.java`/`.kt`(서버)·`.rb`·`.py`(Django/FastAPI/Flask)·`.ts`(Express/Nest)·SQL·migration |
| **프론트** | `.tsx`·`.jsx`·`.vue`·`.svelte`·`components/`·`hooks/`·`useState`·`useEffect`·CSS·`pages/`·`app/`(Next) |
| **Android(AOS)** | `.kt`·`.java` + `Activity`·`Fragment`·`ViewModel`·`Compose`·`AndroidManifest.xml`·`build.gradle` |
| **iOS** | `.swift`·`.m` + `UIViewController`·`SwiftUI`·`View`·`@State`·`Info.plist`·`.xcodeproj` |
| **AI/ML** | `.py` + `torch`·`tensorflow`·`sklearn`·`transformers`·`pandas`·`numpy`·`train`·`model`·`dataset`·`prompt`·LLM SDK |

판정 애매하면 1줄 확인. 한 파일이 여러 신호면 멀티파트로 취급.

## 🖥 백엔드 렌즈 (서버·API·데이터)

**역할 우선순위**: 정확성 > 상태/동시성 > 계약 > 보안 > 에러 > 성능. 데이터 정합과 동시성이 생명.

**강조축 발현형**:
- **상태·동시성**: 동시 요청의 경합 자원(잔액·재고·카운터), check-then-act 비원자성, 분산 락, DB 트랜잭션 격리수준(팬텀·더티리드), 멱등성(재시도·중복 메시지·웹훅 재전송)
- **계약**: API 하위호환(필드 제거·타입 변경·null 시작), 스키마 마이그레이션 + 롤백, 이벤트/메시지 스키마 버전, 무중단 배포 시 구·신 버전 공존
- **에러·자원**: DB 커넥션·트랜잭션·파일 핸들이 모든 경로에서 반환되나, 외부 호출 타임아웃·서킷브레이커, 부분 실패 보상(결제 성공+후속 실패)
- **보안**: SQL/NoSQL 인젝션, authz를 매 엔드포인트 서버에서, IDOR(객체 직접참조), 레이트리밋, 대량 조회 권한, 민감정보 로깅
- **성능**: N+1 쿼리, 인덱스 없는 조회, 루프 내 호출, 페이지네이션 없는 전체 로드, 커넥션풀 고갈

**백엔드 레드플래그**: 트랜잭션 경계 밖 외부 IO · 멱등키 없는 결제/생성 · 마이그레이션에 롤백 없음 · 사용자 입력으로 쿼리 문자열 조립 · 권한 체크 누락 엔드포인트.

## 🌐 프론트엔드 렌즈 (웹·React/Vue 등)

**역할 우선순위**: 정확성(상태관리) > 성능(렌더) > 보안(XSS) > 접근성 > 에러. UI 상태의 정합과 누수가 핵심.

**강조축 발현형**:
- **상태·정확성**: 상태 동기화(서버 상태 vs 로컬), stale closure(오래된 클로저로 옛 값 참조), 파생 상태 중복, 낙관적 업데이트 롤백, race(빠른 연속 요청의 응답 순서 역전)
- **성능(렌더)**: 불필요 리렌더(키 누락·인라인 객체/함수·의존성 배열 오류), 거대 리스트 가상화 부재, 무거운 계산 매 렌더, 번들 크기·코드 스플리팅
- **자원 누수(에러축)**: `useEffect` cleanup 누락(이벤트 리스너·타이머·구독·AbortController), 언마운트 후 setState, 메모리 누수
- **보안**: XSS(`dangerouslySetInnerHTML`·`v-html`·미이스케이프 출력), 토큰을 localStorage 노출, 오픈 리다이렉트, 민감정보 클라이언트 노출
- **로딩/에러 UI 상태**: 로딩·빈·에러·부분로드 상태 처리, 에러 바운더리, 네트워크 실패 재시도
- **접근성**: 의미 태그·`alt`·라벨·키보드 포커스·대비·ARIA (역할상 자주 누락)

**프론트 레드플래그**: `useEffect` 의존성 배열 오류로 무한 루프/누락 · cleanup 없는 구독 · 미이스케이프 사용자 입력 렌더 · 키 없는 리스트 · 클라이언트에 비밀키.

## 🤖 Android 렌즈 (AOS · Kotlin/Java)

**역할 우선순위**: 상태(생명주기) > 에러(누수·크래시) > 성능(메인스레드) > 정확성. 생명주기와 메모리 누수가 생명.

**강조축 발현형**:
- **상태·생명주기**: Configuration change(화면 회전)로 상태 소실, `Activity`/`Fragment` 재생성, `ViewModel`로 상태 보존, `savedInstanceState`, 백스택, 프로세스 종료 후 복원
- **자원 누수(에러축)**: Context 누수(`Activity` 참조를 오래 보유·정적 참조·내부 클래스), 리스너·콜백 해제 누락, `Cursor`/스트림 미닫힘, 코루틴 스코프 누수(`viewModelScope`·`lifecycleScope` 안 쓰고 `GlobalScope`)
- **성능(ANR)**: 메인 스레드에서 IO·네트워크·DB·무거운 연산 → ANR, `Dispatchers.IO` 미사용, 비트맵 메모리
- **정확성**: Kotlin null 안전(`!!` 강제 언래핑·플랫폼 타입), 코루틴 취소·예외 전파(`SupervisorJob`), `Flow` 수집 생명주기(`repeatOnLifecycle`)
- **보안·권한**: 런타임 권한 확인, exported 컴포넌트, 암호화 저장(`EncryptedSharedPreferences`), 딥링크 검증, 평문 통신
- **계약**: API 레벨 호환·deprecated API, ProGuard/R8 규칙

**Android 레드플래그**: `GlobalScope` 사용 · `Activity` Context 정적 보유 · 메인 스레드 블로킹 IO · `!!` 남용 · 화면 회전 시 상태 소실 무처리 · exported=true 검증 없는 컴포넌트.

## 🍎 iOS 렌즈 (Swift/ObjC · SwiftUI/UIKit)

**역할 우선순위**: 에러(메모리·크래시) > 상태 > 성능(메인스레드) > 정확성. retain cycle과 메인스레드 위반이 생명.

**강조축 발현형**:
- **자원·메모리(에러축)**: retain cycle(클로저의 `self` 강참조 — `[weak self]`/`[unowned self]` 누락), 델리게이트 `weak` 누락, `Timer`/옵저버 해제 누락, 강참조 순환
- **정확성**: 옵셔널 강제 언래핑(`!`)·암묵적 언래핑 크래시, `guard let`/`if let` 누락, 배열 인덱스 범위, 형변환(`as!`) 실패
- **상태·동시성**: UI 업데이트는 메인 스레드(`DispatchQueue.main`/`@MainActor`), GCD·`async/await`·actor 격리, 데이터 레이스, `@State`/`@Published`/`@ObservedObject` 소유·갱신, Combine 구독(`AnyCancellable`) 보관
- **성능**: 메인 스레드 블로킹 IO, 무거운 `body` 재계산(SwiftUI), 이미지 디코딩, 리스트 재사용
- **생명주기**: 앱 상태 전이(background/foreground), 화면 전환 시 자원 정리
- **보안**: Keychain 사용(평문 저장 금지), ATS(평문 통신), 민감정보 로깅·스크린샷

**iOS 레드플래그**: 클로저 `self` 강참조 캡처 · 옵셔널 강제 언래핑 남용 · 백그라운드 스레드에서 UI 갱신 · 델리게이트 strong · `AnyCancellable` 미보관으로 즉시 해제.

## 🧠 AI/ML 렌즈 (Python · 학습/추론/LLM)

**역할 우선순위**: 정확성(데이터·수치) > 재현성 > 보안(프롬프트·PII) > 성능(비용). 조용한 오류(틀려도 안 죽음)가 가장 위험.

**강조축 발현형**:
- **데이터 정확성**: train/test 누수(전처리·스케일러를 split 전에 fit, 타깃 누수, 시계열 미래 정보 유입), 라벨 정합, 클래스 불균형 무시, 결측·이상치 처리, 데이터 분포 드리프트
- **재현성**: 시드 고정(`random`·`numpy`·`torch`·CUDA), 비결정 연산, 데이터 버전·체크포인트, 환경·의존성 고정
- **수치 안정성**: NaN/Inf 전파, `log(0)`·0 나눗셈, float overflow, 차원·브로드캐스팅 오류(조용한 잘못된 결과), 정규화 누락
- **평가 지표 오용**: 불균형에 accuracy만, 잘못된 평균(macro/micro), 데이터 누수된 검증, 메트릭과 손실 불일치, 오프라인-온라인 갭
- **LLM 특화 보안**: 프롬프트 인젝션(사용자 입력이 시스템 프롬프트 오염), PII가 프롬프트·로그·학습데이터에 유입, 출력 검증 없이 실행(코드·SQL), 환각을 사실로 사용, 비밀키 노출
- **성능·비용**: 토큰·API 비용 폭증, 배치·캐시 미사용, GPU 메모리(배치 크기·gradient accumulation), 불필요 재학습/재추론, 동기 호출 직렬화
- **계약**: 모델 버전·입출력 스키마, 전처리-학습-추론 일관성(skew), 모델 롤백

**AI/ML 레드플래그**: split 전 전처리 fit(데이터 누수) · 시드 미고정 · NaN 무검사 · 사용자 입력 프롬프트 직접 결합(인젝션) · PII가 프롬프트·로그에 · LLM 출력 검증 없이 실행 · 불균형 데이터에 accuracy만.

## 🔀 멀티파트 PR — 파트 경계 계약 (가장 중요)

한 PR이 여러 파트를 건드리면 각 파트 결함보다 **파트 사이 계약 불일치**가 더 자주·크게 터진다. Phase 1.5 파급과 연동해 반드시 본다:

| 경계 | 확인할 것 |
|---|---|
| 백엔드 ↔ 프론트/앱 | API 응답 형태·필드·null·에러 코드 변경이 클라이언트를 깨나. 버전·하위호환 |
| 백엔드 ↔ DB | 스키마 변경 마이그레이션·롤백, 무중단 배포 중 구·신 코드 공존 |
| 프론트 ↔ 앱 ↔ 백엔드 | 같은 기능을 세 곳이 각자 검증 — 규칙(한도·권한)이 일치하나, 서버가 최종 권위인가 |
| AI ↔ 백엔드 | 모델 입출력 스키마, 전처리 일관성(학습-서빙 skew), 타임아웃·폴백 |
| 공통 계약 | 같은 버그/같은 수정이 여러 파트에 필요한가(횡단 일관성) |

→ 멀티파트는 "각 파트 OK"로 끝내지 말고 **"파트가 맞물리는 지점이 OK인가"**를 별도 결함으로 본다.
